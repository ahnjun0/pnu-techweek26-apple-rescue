# A* vs D* Lite — 재 보고 내린 결론

## 왜 재 봤나
"대회 환경이 어떨지 모르니 D* Lite도 한 번 시도해 보라" 는 요청.
D* Lite 는 "지도가 조금 바뀌었을 때 처음부터 다시 풀지 않고 고쳐 쓰는" 계획기다.

## 구현
`dstar.py` — A* 와 같은 규칙(8방향, 대각선은 양옆이 둘 다 열려야 함, 칸별 비용 배수)을
쓴다. `tests/test_dstar.py` 13개가 **A* 와 경로 비용이 같은지** 직접 비교한다.

### 구현하며 만난 함정 (기록)
`heapq` 에는 삭제가 없어서 낡은 항목을 건너뛰어야 한다. 처음엔 "키가 다르면 낡은 것"
으로 판정했는데, **같은 키로 두 번 들어간 항목은 둘 다 유효**해서 두 번째가
`g` 를 `inf` 로 되돌리고 무한 반복에 빠졌다 (16개 칸이 6만 번 처리됐다).
항목마다 일련번호를 붙여 최신 것만 유효하게 하고, 이미 정리된 칸(`g == rhs`)은
큐에서 나와도 건드리지 않도록 고쳤다.

## 측정 (160×160 격자, practice.wbt 를 닮은 지도)

| 상황 | A* | D* Lite | 누가 유리 |
|---|---|---|---|
| 처음 한 번 풀기 | **1.7 ms** | 18.6 ms | A* 11배 |
| 경로에서 먼 곳이 바뀜 | 1.8 ms | **0.1 ms** | D* Lite 18배 |
| 경로 위에 사람 크기 장애물 | **1.7 ms** | 12.4 ms (첫 복구) | A* 7배 |
| 길이 완전히 막힘 (없음 증명) | **15.3 ms** | 168 ms | A* 11배 |
| **목표를 3번 바꿈** | **7.8 ms** | 92.5 ms | A* 12배 |

## 결론: 지금 구조에는 A* 가 맞다

**결정적인 이유는 속도가 아니라 "목표가 계속 바뀐다" 는 것이다.**
D* Lite 는 목표 하나를 고정해 놓고 거꾸로 푼 결과를 재사용한다.
우리 탐색은 프론티어를 고를 때마다 목표가 바뀌므로, 그때마다 처음부터 다시
만들어야 한다 — 그러면 제일 비싼 연산만 반복하게 된다.

게다가 A* 는 이미 1.7 ms 다 (틱 예산 32 ms). 병목이 아니다.

## 그래도 쓸 자리는 있다
목표가 **오래 고정되는** 구간에서는 D* Lite 가 유리하다:
- **RETURN 단계** — 목표가 시작 지점 하나로 끝까지 고정된다
- **APPROACH 단계** — 특정 목표물 하나로 다가가는 동안 고정된다

이 두 구간에서 지도가 계속 자라는 동안 재계획이 잦다면 D* Lite 가 18배 싸다.
지금은 A* 가 충분히 빨라 굳이 바꾸지 않았지만, 대회 맵이 훨씬 크면
(예: 20 m × 20 m, 400×400 격자) A* 의 첫 풀이가 수십 ms 로 늘어나므로
그때는 이 두 구간에 D* Lite 를 끼우는 것이 이득이다. 코드는 준비돼 있다.

## 쓰는 법
```python
import dstar
engine = dstar.DStarLite(blocked, cost, goal_cell)
path = engine.plan(start_cell)          # 처음
engine.update(new_blocked, new_cost, changed_cells)
path = engine.plan(new_start_cell)      # 바뀐 부분만 고쳐 쓴다
```
`blocked`/`cost` 는 `planner.inflate()` / `planner.cost_layer()` 가 만들어 준다.
