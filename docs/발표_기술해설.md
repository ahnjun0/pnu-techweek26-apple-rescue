## 0. 한 장 요약

**임무**: 시작점 $(-0.3,\,-7.5)$ 에서 출발 → 모르는 집을 스스로 탐색 → 빨간 사과 2개를 찾아 가까이 감 → 시작점 복귀.
금지: GNSS(GPS), Webots 가 주는 절대 위치(Supervisor), 기본 로봇 속도 초과.

**한 틱의 순서** (`controllers/sar_controller/sar_controller.py`)

1. 엔코더·나침반 읽기 → 위치 $(x, y, \theta)$ 갱신
2. (2틱마다) 카메라 영상 → 사과 후보 갱신
3. LiDAR → 지도 갱신 → 사람 후보 갱신
4. 상태 기계가 목표를 정하고, 필요하면 A\* 로 경로를 다시 짠다 (0.3초마다 또는 경로가 막히면)
5. DWA 가 이번 틱의 $(v, \omega)$ 를 고른다 → 바퀴 각속도로 바꿔 모터에 넣는다

## 1. 좌표계와 단위

### 1.1 월드 좌표 (ENU)

Webots 기본 좌표계는 **ENU**: $x$ 동쪽, $y$ 북쪽, $z$ 위. 방향 $\theta$ 는 $+x$ 축에서 **반시계**가 $+$ 다.
시작 자세는 $(x_0, y_0, \theta_0) = (-0.3,\ -7.5,\ \pi)$ — 서쪽을 보고 선다.

### 1.2 로봇 좌표 ↔ 월드 좌표

로봇 기준 점 $(p_x, p_y)$ (앞 $+x$, 왼쪽 $+y$)를 월드로:

$$
\begin{pmatrix} w_x \\ w_y \end{pmatrix}
= \begin{pmatrix} x \\ y \end{pmatrix}
+ \begin{pmatrix} \cos\theta & -\sin\theta \\ \sin\theta & \cos\theta \end{pmatrix}
\begin{pmatrix} p_x \\ p_y \end{pmatrix}
$$

반대(월드 → 로봇)는 전치행렬 $R(\theta)^\top = R(-\theta)$ 를 쓴다.

### 1.3 격자 좌표 (지도의 칸)

지도는 $320 \times 320$ 칸, 칸 하나 $r = 0.05\ \text{m}$, 원점 $(x_o, y_o) = (-14,\ -15)$. 즉 $16\times16\ \text{m}$ 를 덮는다.

$$
\text{col} = \left\lfloor \frac{x - x_o}{r} \right\rfloor,\qquad
\text{row} = \left\lfloor \frac{y - y_o}{r} \right\rfloor,\qquad
x_{\text{중심}} = x_o + (\text{col} + 0.5)\,r
$$

**규칙**: 이 변환은 `common.to_cell` / `common.to_world` 두 함수에만 있다. 다른 곳에서 `x / r` 를 직접 쓰면 `check_rules.sh` 가 막는다 — 변환이 여러 곳에 흩어지면 반드시 한쪽이 틀리기 때문이다.

### 1.4 LiDAR 배열의 각도

LiDAR 는 360개 거리를 배열로 준다. $i$ 번째 광선의 로봇 기준 각도:

$$
\alpha_i = -\pi \;-\; i\cdot\frac{2\pi}{360}\qquad(\text{wrap 해서 } [-\pi, \pi))
$$

즉 **인덱스 0 은 로봇 뒤쪽**, 인덱스가 늘면 **시계 방향**. 문서로 정하지 않고 실험(`debug/lidar_orientation.py`, 오른쪽에 상자를 두고 확인)으로 정했다.
주최 측 `tb3_lidar.py` 도 `[180]=앞, [0]=뒤, [90]=왼쪽, [270]=오른쪽` 으로 같다.

### 1.5 카메라 (핀홀 모델)

640×480, 수평 시야각 $\text{FOV} = 1.0472\ \text{rad} = 60°$. 초점거리(픽셀):

$$
f = \frac{W/2}{\tan(\text{FOV}/2)} = \frac{320}{\tan 30°} \approx 554.3\ \text{px}
$$

$u$ 번째 세로줄이 보는 방향(오른쪽이 음수):

$$
\beta(u) = -\arctan\!\left(\frac{u - (W-1)/2}{f}\right)
$$

부호는 실측으로 확인했다 (왼쪽 기둥의 실제 방향 +22.9°, 측정 +22.9°).
카메라 위치: 로봇 중심보다 앞 $0.02\ \text{m}$, 바닥 위 $h = 0.073\ \text{m}$ (`TurtleBot3Burger.proto:38` 슬롯 높이 0.153 + 대회 월드의 카메라 −0.08).

## 3. 위치 추정 (Localization)

### 3.1 무엇을 하나

"나는 지금 어디에 있는가" $(x, y, \theta)$ 를 **절대 위치 없이** 계속 추적한다. 방법은 **추측 항법(dead reckoning)**: 매 틱 바퀴가 굴러간 만큼 더한다.

### 3.2 식

**① 바퀴가 굴러간 거리** — 엔코더 누적각의 이번 틱 변화량 $\Delta\phi$ 와 바퀴 반지름 $r_w$:

$$
\Delta s_L = r_w\,\Delta\phi_L,\qquad \Delta s_R = r_w\,\Delta\phi_R,\qquad
\Delta s = \frac{\Delta s_L + \Delta s_R}{2}
$$

**② 방향 — 나침반에서 바로 읽는다**

나침반은 "북쪽(월드 $+y$)이 로봇 좌표계에서 어느 쪽인가"를 준다. 로봇이 $\theta$ 만큼 돌아 있으면

$$
\mathbf{m} = R(-\theta)\begin{pmatrix}0\\1\end{pmatrix}
= \begin{pmatrix}\sin\theta\\ \cos\theta\end{pmatrix}
\quad\Longrightarrow\quad
\boxed{\ \theta = \operatorname{atan2}(m_x,\ m_y)\ }
$$

나침반은 **절대 방위** 라 적분하지 않는다 → 방향 오차가 쌓이지 않는다.
(나침반이 없을 때의 대안: 자이로 적분 $\theta_k = \theta_{k-1} + \omega_z\Delta t$, 그것도 없으면 $\theta_k = \theta_{k-1} + \frac{\Delta s_R - \Delta s_L}{B_{\text{odom}}}$.)

**③ 위치 — 중점법(midpoint)으로 적분**

$$
\bar\theta = \theta_{k-1} + \tfrac12\,\operatorname{wrap}(\theta_k - \theta_{k-1}),\qquad
x_k = x_{k-1} + \Delta s\cos\bar\theta,\qquad
y_k = y_{k-1} + \Delta s\sin\bar\theta
$$

틱 시작 각도 대신 **틱 중간 각도** 로 가야 곡선 주행 오차가 준다.

| 기호 | 값 | 근거 |
|---|---|---|
| $r_w$ (명령용) | 0.033 m | `TurtleBot3Burger.proto:116,162` |

### 3.4 왜 이렇게 했나 (측정)

- **나침반이 가장 정확하다** — 빈 월드 1 m 정사각형 주행 후 최종 오차: 나침반 0.07 cm, 자이로 0.07 cm, 엔코더만 6.12 cm (`debug/odometry_check.py`).
- **바닥에 맞춘 바퀴 반지름 보정** — apartment 에서는 직진 38구간 모두 "바퀴로 계산한 거리 / 실제 거리" 가 **0.983** (0.976~0.988) 이었다. 빈 월드에서는 같은 64 ms 로 돌려도 1.002. 실제 로봇을 바닥에 맞춰 보정하듯 오도메트리용 반지름만 $0.033/0.983$ 으로 바꿨다. 보정 뒤 같은 비율이 **1.0015**. 바퀴 명령은 기하값을 그대로 쓰므로 속도 규칙과 무관하다.

### 3.5 약점 — 바퀴 헛돎·미끄러짐

추측 항법은 "바퀴가 돈 만큼 몸도 움직였다"를 가정한다. 이 가정이 깨지면:

| 상황 | 엔코더 | 실제 | 결과 |
|---|---|---|---|
| 벽에 끼어 헛돎 | 전진했다 | 제자리 | 추정이 앞으로 튄다 (연습 중 49 m 까지) |
| **카펫 턱에 바퀴 하나 걸린 채 회전** | 제자리 회전 | 턱을 따라 옆으로 미끄러짐 | 5초에 +47 cm (apartment 302~308초) |

카펫은 두께 2 cm (`Carpet.proto:209`) 라 LiDAR(17 cm 높이)에 안 보인다. 방향은 나침반이라 틀어지지 않지만 **위치** 가 틀어진다.
감지 신호: 평소엔 명령 회전 대비 나침반 회전이 0.87~1.14 인데, 카펫 턱에서는 **0~0.3** 으로 떨어졌다.

**미끄러짐 감지** (`mission._check_slip`, `SLIP_ENABLED`, 커밋 `5a18c51`, 측정 전이라 기본 꺼짐):
바퀴로 계산한 회전 속도와 나침반 회전 속도를 비교한다.

$$
\omega_{\text{바퀴}} = \frac{\Delta s_R - \Delta s_L}{B_{\text{odom}}\,\Delta t},\qquad
\omega_{\text{나침반}} = \frac{\operatorname{wrap}(\theta_k - \theta_{k-1})}{\Delta t},\qquad
\text{미끄러짐} \iff |\omega_{\text{바퀴}} - \omega_{\text{나침반}}| > 0.6\ \text{rad/s 가 } 0.3\text{초 이상}
$$

잡히면 1초 후진하고, 그 자리(반경 0.10 m)를 계획용 지도에 벽으로 찍어 다시 가지 않는다.
녹화 재생에서 카펫 사건(302~309초)과 185 cm 튐(384~395초)을 모두 잡았다.

### 3.6 스캔 매칭 (Scan Matching) — 구현했고, 지금은 꺼져 있다

**생각**: 벽은 움직이지 않는다. 지금 LiDAR 로 본 모양을 지금까지 그린 지도에 겹쳐 보고, 가장 잘 맞는 곳으로 위치를 고친다.

**① 격자 매칭** (`scanmatch.match`, 강의 p63-72 계열 — correlative scan matching)

- 지도에서 "각 칸이 가장 가까운 벽에서 몇 칸 떨어졌나"를 미리 계산한다 (거리 변환, likelihood field) → $D(c)$.
- 현재 위치 주변 $\pm 10\ \text{cm}$ (칸 단위), $\pm 3°$ 를 다 대입해 본다:

$$
(\Delta x^\ast, \Delta y^\ast, \Delta\theta^\ast) = \arg\min_{\Delta}\ \frac1N\sum_{i=1}^{N} D\!\left(\text{cell}\big(T_{\Delta}\,\mathbf{p}_i\big)\right)
$$

- 제자리보다 뚜렷하게 좋아질 때만, 그리고 성분별로 근거가 있는 축만 옮긴다 (복도에서 진행 방향으로 미끄러지지 않게).

**② 정밀 매칭** (`scanmatch.match_fine`, 오늘 새로 만듦 — Hector SLAM 계열)

$D$ 를 **쌍선형 보간** 해서 연속값으로 만들고, 위치 $(\Delta x, \Delta y)$ 만 가우스-뉴턴으로 푼다 (방향은 나침반이 이미 정확):

$$
\min_{\boldsymbol\delta}\ \sum_i d_i(\boldsymbol\delta)^2,\quad d_i(\boldsymbol\delta) = D(\mathbf{p}_i + \boldsymbol\delta),\qquad
J_i = \nabla D(\mathbf{p}_i + \boldsymbol\delta)
$$

$$
(J^\top J)\,\Delta\boldsymbol\delta = -J^\top \mathbf{d}
$$

- $J^\top J$ (2×2 정보행렬)를 고윳값 분해해서, 고윳값이 작은 방향(= 근거가 없는 방향, 예: 긴 복도의 진행 방향)은 **고치지 않는다**.
- 거리장이 벽에서 V 자라 한 걸음이 넘어가기 쉽다 → 비용이 줄 때까지 걸음을 반씩 줄인다 (백트래킹).
- 벽에서 0.2 m 넘게 떨어진 점(지도에 없는 사람·새 물체)은 비용에서 뺀다.

| 격자 매칭 | 37.5 cm | 98.9 cm |
| **정밀 매칭** | **21.2 cm** | **86.3 cm** |

**그런데 왜 꺼져 있나**: 실제 주행(닫힌 고리)에서는 고친 위치 때문에 경로가 바뀌고, 결과가 실행마다 크게 갈렸다. 격자 매칭 + 반지름 보정은 오차 42 cm·실제로 시작점 0.53 m 앞 복귀까지 갔지만 사과 1/2·875초였다. 정밀 매칭은 위치는 6 cm 로 정확했지만 탐색이 61초에 "갈 곳 없음"으로 끝났다(가짜 벽 문제, 7장). **위치 추정은 확실히 좋아지지만, 전체 점수가 좋아진다는 측정이 아직 없다** — 그래서 기본값은 꺼 두고 계속 재고 있다.

### 3.7 예상 질문

- **Q. 칼만 필터나 파티클 필터(AMCL)는 왜 안 썼나?**
  A. 강의 p73 이 "오도메트리만으로도 위치 추정 가능" 을 전제한다. 우리 방향은 나침반이라 누적 오차가 없고, 남는 오차는 위치뿐이다. AMCL 은 **미리 있는 지도** 에서 위치를 찾는 방법이라, 지도를 새로 그리는 이번 과제에는 SLAM(동시 위치추정·지도작성)이 맞다. 스캔 매칭이 그 SLAM 의 위치 보정 부분이다.
- **Q. 스캔 매칭 결과를 칼만 필터로 섞으면?**
  A. 맞는 방향이다. 지금 격자 매칭은 결과로 위치를 **덮어쓴다** — 틀린 매칭 한 번이 그대로 누적된다. "매칭이 얼마나 확실한가"(정보행렬 $J^\top J$)로 가중해 섞으면 칼만 갱신과 같아진다. 정밀 매칭이 그 정보행렬을 이미 계산한다.
- **Q. 자이로·가속도계는 왜 안 쓰나?** A. 방향은 나침반이 누적 오차 없이 준다 (실측 0.07 cm). 가속도를 두 번 적분하면 잡음이 제곱으로 커진다.

## 4. 지도 (Occupancy Grid)

### 4.1 무엇을 하나

$16\times16\ \text{m}$ 를 5 cm 칸으로 나누고, 칸마다 "벽일 확률" $p$ 를 들고 있다. LiDAR 광선이 **지나간 칸은 비었다**, **멈춘 칸은 막혔다** 는 증거다.

### 4.2 식 — 베이즈 필터의 log-odds 형태 (강의 p53-55)

확률 대신 로그 오즈를 저장한다:

$$
l = \log\frac{p}{1-p}\qquad\Longleftrightarrow\qquad p = \frac{1}{1 + e^{-l}}
$$

베이즈 갱신 $P(\text{벽}\mid z_{1:t}) \propto P(z_t \mid \text{벽})\,P(\text{벽}\mid z_{1:t-1})$ 은 로그 오즈에서 **덧셈** 이 된다 (사전확률 0.5, $l_0 = 0$):

$$
l_t = l_{t-1} + \underbrace{\log\frac{P(\text{벽}\mid z_t)}{1 - P(\text{벽}\mid z_t)}}_{\text{역센서 모델}}
$$

| 관측 | 더하는 값 | 해당 확률 |
|---|---|---|
| 광선이 이 칸에서 멈춤 (맞음) | $+0.9$ | $p = 0.71$ |
| 광선이 이 칸을 지나감 (빔) | $-0.4$ | $p = 0.40$ |

범위 제한 $l \in [-3,\ +5]$ ($p \in [0.047,\ 0.993]$) — 한 번 굳은 칸도 새 증거로 바뀔 수 있게.

판정: 막힘 $l \ge 0.8$ ($p \ge 0.69$), 빔 $l \le -0.4$, 그 사이는 **모름**.
→ 벽은 **한 번** 맞으면 바로 "막힘" ($0.9 \ge 0.8$), 빈 곳도 **한 번** 지나가면 "빔".
→ 굳은 벽($+5$)이 빈 칸으로 바뀌려면 광선이 $\lceil (5 + 0.4)/0.4 \rceil = 14$ 번 지나가야 한다.

### 4.3 광선 긋기

로봇 칸에서 끝점 칸까지 **브레젠험 직선** 으로 칸을 나열한다. 끝점이 실제로 맞은 것이면 그 칸 $+0.9$, 나머지 $-0.4$.
사거리 밖(3.0 m 넘게, 또는 무한대)이면 3.0 m 까지만 "빔"으로 긋는다. 0.12 m 보다 가까운 값은 믿지 않는다.

### 4.4 예상 질문

- **Q. 칸 크기 5 cm 는 왜?** A. 로봇 반경 0.13 m 의 약 1/3. 더 잘게 하면 A\* 가 느려지고, 크게 하면 좁은 문(약 0.7 m)이 막혀 보인다.
- **Q. 사람이 지나가면 지도에 벽이 남지 않나?** A. 남는다 — 실제로 문 한가운데 15 cm 짜리 점이 남아 방이 갇힌 것처럼 보였다(7.4). 광선이 다시 지나가면 지워지지만 14번이 필요하다. 그래서 복귀는 "지나온 길 되짚기"로 대비했다.

## 5. 인지 ① — 빨간 사과

### 5.1 파이프라인

```
영상 → HSV → 빨강 마스크 → 연결 요소(덩어리) → 거리 두 번 재기 → 모양 검사 → (YOLO 확인) → 위치 → 25번 보면 확정
```

### 5.2 빨강 마스크 (강의 p29-38)

OpenCV HSV: 색상 $H \in [0, 179]$, 채도 $S$, 명도 $V \in [0, 255]$. 빨강은 색상환 양끝에 걸쳐 있어 **두 구간** 이다:

$$
\text{빨강} \iff \big(H \le 10 \ \lor\ H \ge 170\big)\ \land\ S \ge 150\ \land\ V \ge 60
$$

채도 하한 150 이 핵심 — 바닥 나뭇결의 붉은 기를 거른다. 25 픽셀보다 작은 덩어리는 잡음.

### 5.3 카메라만으로 거리 재기 — 두 가지 방법이 서로 맞아야 한다

사과는 LiDAR(17 cm 높이)보다 **낮아서** LiDAR 로 거리를 못 잰다. 그래서 카메라 한 장으로 두 번 잰다.

**(a) 크기로** — 반지름 $R = 0.05\ \text{m}$ 인 공이 폭 $w$ 픽셀로 보이면, 반각 $\gamma = \arctan\frac{w/2}{f}$ 이고

$$
d_{\text{크기}} = \frac{R}{\sin\gamma}
$$

**(b) 바닥 접점으로** — 공의 밑동(덩어리 맨 아래 행 $v_b$)은 바닥에 닿아 있고, 카메라는 바닥 위 $h = 0.073\ \text{m}$ 다. 밑동을 내려다보는 각 $\delta = \arctan\frac{v_b - (H-1)/2}{f}$ 이면

$$
d_{\text{바닥}} = \frac{h}{\tan\delta}\qquad(\delta \le 0 \text{ 이면 수평선 위 → 바닥에 놓인 물체가 아니다})
$$

**판정**: 진짜 바닥의 사과라면 두 값이 같아야 한다.

$$
|d_{\text{크기}} - d_{\text{바닥}}| \le 0.3\,d_{\text{바닥}},\qquad
\tfrac{2}{3} \le \frac{\text{세로}}{\text{가로}} \le 1.5,\qquad
d = \tfrac12(d_{\text{크기}} + d_{\text{바닥}}) \le 3\ \text{m}
$$

| 가짜 | 무엇이 걸렀나 |
|---|---|
| 가까운 소화기 (세로로 김) | 두 거리가 81% 어긋남 |
| 먼 소화기 (23×72 픽셀) | 두 거리는 29% 로 통과 → **세로/가로 3.1** 로 걸림 |
| 바닥에 누운 캔 (26×11) | **세로/가로 0.42** 로 걸림 |
| 식탁 위 과일 | 밑동이 수평선 위 → 바닥 물체 아님 |

월드 좌표: 방향 $\beta$(1.5절), 카메라 위치 $\mathbf{c}$ 에서

$$
\mathbf{t} = \mathbf{c} + d\begin{pmatrix}\cos(\theta + \beta)\\ \sin(\theta + \beta)\end{pmatrix}
$$

### 5.4 YOLO 확인 (강의 p42-50) — 빨간 덩어리가 모양 검사를 통과한 장에서만

- 모델: YOLO11n (COCO 80종), CPU 추론, 확신도 0.1 이상. 모델 위치는 주최 측 예시와 같은 `models/YOLO/yolo11n.pt`.
- 덩어리 중심을 덮는 YOLO 상자의 라벨로 판정:
  - `sports ball`·`apple`·`orange` → **받는다** (녹화 23장 중 23장이 sports ball)
  - `bottle`·`cup`·`vase` 등 → **버린다**
  - 아무것도 없음 → **단서** 로만 남기고 가까이 가서 다시 본다 (멀리 있는 사과는 YOLO 가 자주 놓친다 — 문지기로 쓰면 사과를 잃는다)
- 비용: 녹화 668장 중 24장에서만 돌았다 (한 장 약 90 ms).

### 5.5 여러 번 보고 확정

같은 물체를 여러 번 본다. 0.45 m 안의 관측은 같은 물체로 묶고 **이동 평균** 으로 위치를 다듬는다:

$$
\mathbf{t}_n = \mathbf{t}_{n-1} + \frac{1}{n}\,(\mathbf{z}_n - \mathbf{t}_{n-1})
$$

$n \ge 25$ 번 보면 확정 (카메라 128 ms 마다 → 최소 3.2초 관찰). 한 번 반짝한 잡음을 거른다.

### 5.6 예상 질문

- **Q. 색만으로 충분한가? 다른 빨간 물체는?** A. 5.3 표처럼 소화기·캔이 실제로 걸렸고, 그래서 거리 두 개의 일치 + 모양 + YOLO 를 겹겹이 뒀다.
- **Q. 왜 LiDAR 로 거리를 안 재나?** A. 사과(지름 10 cm)가 LiDAR 평면(17 cm)보다 낮다. LiDAR 는 사과 뒤의 벽을 잰다.
- **Q. 거리가 틀리면?** A. 두 방법 모두 실제보다 15~20% 짧게 나오는 경향이 있었다(표본 3개, 원인 미확정). 판별에는 지장이 없고, 가까이 갈수록 오차가 줄어든다.

## 6. 인지 ② — 사람과 칼만 필터

### 6.1 사람 후보 — LiDAR 로 "지도에 없는 것"

1. 광선을 이웃 간격이 0.2 m 넘게 벌어지는 곳에서 **조각** 으로 자른다.
2. 조각의 점 절반 이상이 지도의 **빈 칸** 위에 있으면 "지도에 없는 물체"다 (모양·색 무관).
3. 벽에 붙은 조각은 표면 잡음이라 버린다.
4. **움직였는가** 로 최종 판정: 최근 9스캔에서 2번 이상 보이고, 그 사이 $0.15\ \text{m/s}$ 이상 움직였어야 사람이다. (고정물은 제자리, 사람은 옮겨 간다.)

### 6.2 등속 칼만 필터 (강의 p76-77, `people.Tracker`)

한 스캔 위치 오차가 약 23 cm 라, 두 스캔의 차이로 낸 속도는 잡음이 사람 속도보다 컸다. 칼만 필터로 여러 스캔을 누적해 **속도를 거른다**.

상태 $\mathbf{x} = (x, y, v_x, v_y)^\top$, 등속 모델 ($\Delta t = 0.064\ \text{s}$):

$$
F = \begin{pmatrix}1&0&\Delta t&0\\0&1&0&\Delta t\\0&0&1&0\\0&0&0&1\end{pmatrix},\quad
G = \begin{pmatrix}\tfrac{\Delta t^2}{2}&0\\0&\tfrac{\Delta t^2}{2}\\\Delta t&0\\0&\Delta t\end{pmatrix},\quad
Q = \sigma_a^2\,GG^\top,\quad
H = \begin{pmatrix}1&0&0&0\\0&1&0&0\end{pmatrix},\quad
R = \sigma_z^2 I
$$

**예측**: $\hat{\mathbf{x}}^- = F\hat{\mathbf{x}},\quad P^- = FPF^\top + Q$

**갱신**: $S = HP^-H^\top + R,\quad K = P^-H^\top S^{-1},\quad \hat{\mathbf{x}} = \hat{\mathbf{x}}^- + K(\mathbf{z} - H\hat{\mathbf{x}}^-),\quad P = (I - KH)P^-$

| 값 | 의미 |
|---|---|
| $\sigma_z = 0.23\ \text{m}$ | 한 스캔 위치 오차 (실측) |
| $\sigma_a = 1.0\ \text{m/s}^2$ | 걷다 멈추고 도는 정도 |
| 게이트 0.6 m | 예측 위치에서 이 안의 측정만 같은 사람 |
| 3번 갱신 후 출력, 0.5초 가려져도 예측으로 유지, 1초 못 보면 버림 | |

**쓰는 곳**: DWA 가 사람의 **앞으로 1.2초 동안 있을 자리** $\mathbf{q} + \mathbf{v}t$ ($t = 0.4, 0.8, 1.2$)를 장애물로 본다. 전역 계획은 사람 둘레 1.2 m 를 비싸게 매긴다 (9.2).

**왜 예측이 중요한가**: Webots 보행자는 로봇을 피하지 않고 경로를 그대로 민다. 이 월드의 보행자 속도는 `--speed=0.2` 로 **로봇 최고 속도와 같다** — 도망쳐서는 못 피하고, 갈 곳을 예측해 비켜야 한다.

**측정 (apartment)**: 보행자와 닿은 시간 — 사람 검출 끔 3.8초 → 켬 0초 → 켬 + 칼만 0초 (완주 350초 → 342초).

## 7. 판단 — 상태 기계

### 7.1 상태와 전이 (강의 p128 FSM)

```
SCAN ──(1.15바퀴)──▶ EXPLORE ──(사과 확정)──▶ APPROACH ──(0.57 m 안 / 40초)──▶ EXPLORE
                        │                                                        
                        ├──(프론티어 없음 & 사과 모자람)──▶ SWEEP (카메라 안 본 곳 둘러보기)
                        │
                        └──(할 일 끝 / 시간 예산)──▶ RETURN ──(시작점 0.25 m 안)──▶ DONE
```

| 상태 | 하는 일 |
|---|---|
| SCAN | 제자리 1.15바퀴 (0.9 rad/s, 약 8초). 카메라(60°)로 시작점 주변을 훑는다 |
| EXPLORE | 프론티어로 간다 (8장). 빨간 것을 보면 그쪽이 먼저 |
| APPROACH | 확정한 사과에서 **0.57 m** 안까지 간다 (가까이 간 거리는 채점하지 않는다) |
| SWEEP | 지도는 다 그렸는데 사과가 모자라면, 카메라가 아직 안 본 빈 칸 중 가까운 곳으로 가서 한 바퀴 돈다 |
| RETURN | 시작점까지 A\*. 지도에 길이 없으면 **지나온 길을 거꾸로** |
| DONE | 멈춤 |

### 7.2 시간 예산 — 언제 돌아서나

제한 시간 $T = 900\ \text{s}$ 안에 **돌아올 시간** 을 남긴다. 집까지 A\* 경로 길이 $L$, 지금까지 평균 속도 $\bar v$ (최소 $0.25\,v_{\max}$):

$$
t_{\text{복귀 시작}} = T - \max\!\left(1.5\cdot\frac{L}{\bar v},\ 30\ \text{s}\right)
$$

경과 시간이 이걸 넘으면 **무엇을 하던 중이든** 복귀한다 (매 틱 검사). 집 근처면 거의 끝까지 탐색하고, 멀면 일찍 돌아선다.

### 7.3 복귀 — 지나온 길 되짚기

주행 중 10 cm 마다 위치를 적어 둔다 → $\{\mathbf{b}_0, \dots, \mathbf{b}_n\}$.
복귀할 때 지도에 길이 3초 넘게 없으면 이 기록을 거꾸로 따라간다. 같은 자리를 두 번 지난 고리는 건너뛴다 — 각 점에서 **0.3 m 안의 가장 오래된 점** 으로 점프:

$$
i \leftarrow \min\{\, j < i \;:\; \lVert \mathbf{b}_j - \mathbf{b}_i \rVert \le 0.3 \,\}\quad(\text{없으면 } i-1)
$$

**근거**: 문 한가운데 보행자 흔적(15 cm 점)이 지도에 벽으로 남아 방이 갇혔다. 로봇은 그 문을 **실제로 두 번 지나왔는데도** 직선으로 집에 가려다 벽에 붙어 200초를 보냈다. 되짚기 후 297.6초에 복귀.

### 7.4 목표물이 없어도 돌아온다

과제의 절반은 복귀다. 예전엔 사과를 못 찾으면 그 자리에서 끝났다 (시작점에서 4.55 m). 지금은 항상 RETURN.

## 8. 탐색 — 프론티어

### 8.1 정의 (강의 p105)

**프론티어 칸** = 빈 칸이면서 상하좌우 중 하나가 모르는 칸.

$$
F = \{\, c \;:\; \text{free}(c) \land \exists\, n \in \mathcal{N}_4(c),\ \text{unknown}(n) \,\}
$$

로봇이 설 수 없는 곳(팽창 영역, 9.1) 안의 칸은 뺀다 — 벽 속에 남은 "모르는 칸" 때문에 탐색이 안 끝나는 것을 막는다.

### 8.2 고르는 법 (단순하게 — 한 가지 규칙)

1. 프론티어 칸을 연결 요소로 묶는다 (4칸 미만은 잡음).
2. 덩어리마다 **설 자리** 를 정한다 (대표 칸이 막혀 있으면 가장 가까운 설 수 있는 칸). 0.7 m 넘게 밀려나면 버린다 — 거기 서도 그 경계를 볼 수 없다.
3. 로봇에서 0.25 m 안이면 버린다 (제자리 반복 방지). 3번 실패한 곳은 블랙리스트.
4. **정말 갈 수 있는지** A\*(대체 목표 없이)로 확인. 안 되면 여유를 줄여(0.28 m) 한 번 더.
5. 점수 = 경로 길이. 가장 짧은 곳으로 간다:

$$
k^\ast = \arg\min_k\ \Big( \lVert \mathbf{x} - \mathbf{w}^{(k)}_0 \rVert + \sum_j \lVert \mathbf{w}^{(k)}_{j+1} - \mathbf{w}^{(k)}_j \rVert \Big)
$$

**왜 이렇게 단순한가**: 크기 가점·회전 비용·카메라 이득 같은 점수를 섞어 봤는데, 섞을수록 결과가 월드마다 들쭉날쭉했다 (`docs/무엇을-빼기로-했나.md`). 최소 규칙으로 16개 연습 월드 46~48/48.

### 8.3 알려진 약점

- 실패한 목표가 블랙리스트에 오르기 전(3번)까지 **다시 뽑힌다** → 같은 방에 세 번 들어가려 함.
- 가짜 벽(보행자 흔적)이 길을 막으면 남은 프론티어가 전부 "갈 수 없음"이 되어 **일찍 포기** 한다 (61초 사례).

## 9. 전역 경로 계획

### 9.1 팽창 (Configuration Space, 강의 p96-99)

로봇을 **점** 으로 보고 계획하기 위해, 벽을 로봇 크기만큼 부풀린다:

$$
\text{blocked}(c) \iff \min_{o \in \text{벽}} \lVert c - o \rVert \le r_{\text{robot}} + m = 0.13 + 0.22 = 0.35\ \text{m}
\quad\lor\quad \text{unknown}(c)
$$

- $r_{\text{robot}} = 0.13$: 몸체 외접 반경 0.110 + 여유.
- $m = 0.22$: 안전거리. 정지거리(0.23 m)와 맞물린다.
- 좁은 문에서 길이 없으면 $m = 0.15$ (반경 0.28 m)로 한 번 더 — "좁은 여유".

### 9.2 칸 비용

기본 1. 사람 $\mathbf{q}$ 둘레 $R_p = 1.2\ \text{m}$ 안은 선형으로 비싸게:

$$
C(n) = 1 + (4 - 1)\cdot\max\!\Big(0,\ 1 - \frac{\lVert n - \mathbf{q}\rVert}{R_p}\Big)
$$

### 9.3 A\* (강의 p103)

$$
f(n) = g(n) + h(n),\qquad g(n') = g(n) + \delta\cdot C(n'),\ \ \delta \in \{1, \sqrt2\}
$$

- 8방향 이동. 대각선은 **옆 두 칸이 모두 열려 있을 때만** (모서리를 스치지 않게).
- 휴리스틱 = 옥타일 거리:

$$
h(n) = \max(|\Delta r|, |\Delta c|) + (\sqrt2 - 1)\min(|\Delta r|, |\Delta c|)
$$

  $C \ge 1$ 이므로 $h$ 는 실제 비용을 **넘지 않는다**(admissible) → A\* 가 최단 경로를 보장한다.
- 6만 칸을 펼쳐도 못 찾으면 실패로 친다.

### 9.4 경로 다듬기

칸 경로는 계단 모양이다. 현재 점에서 **직선으로 보이는(막힌 칸을 지나지 않고, 원래 길보다 비싸지 않은)** 가장 먼 점까지 건너뛰어 꺾이는 곳만 남긴다.

### 9.5 다시 계획하는 때

0.3초마다, 그리고 새로 본 장애물이 지금 경로를 막으면 즉시.

### 9.6 예상 질문

- **Q. 왜 Dijkstra 가 아니라 A\*?** A. 같은 최단 경로를 주면서, 휴리스틱으로 목표 쪽부터 펼쳐 훨씬 적게 탐색한다. D\* Lite 도 구현해 비교했지만(`docs/계획기-비교-Astar-vs-DstarLite.md`) 지도 320×320 에서는 A\* 로 충분했다.
- **Q. 경로가 벽에 너무 붙지 않나?** A. 팽창 0.35 m 가 곧 최소 거리다. DWA 가 여기에 0.28 m 여유를 한 번 더 확인한다.

## 10. 지역 계획·제어 — DWA

경로는 **좌표 목록** 일 뿐이다. 매 틱 "지금 바퀴에 무엇을 넣을까"는 DWA(Dynamic Window Approach, 강의 p109)가 정한다.

### 10.1 조준점

경로 위에서 로봇에 가장 가까운 점부터 경로를 따라 $L = \max(0.20,\ v_{\max}T) = 0.24\ \text{m}$ 앞의 점 $\mathbf{g}$.

### 10.2 동적 창 — 지금 속도에서 낼 수 있는 후보만

가속 한계 $a = 0.6\ \text{m/s}^2$, $\alpha = 4.0\ \text{rad/s}^2$, 창 폭 $\tau = 0.133\ \text{s}$:

$$
V_d = \Big\{(v, \omega)\ \Big|\ v \in [\max(-0.06,\ v_c - a\tau),\ \min(0.20,\ v_c + a\tau)],\ \ 
\omega \in [\max(-1.2,\ \omega_c - \alpha\tau),\ \min(1.2,\ \omega_c + \alpha\tau)]\Big\}
$$

$v$ 7개 × $\omega$ 17개 = **119 후보**. 창 폭이 $\pm0.08\ \text{m/s}$, $\pm0.53\ \text{rad/s}$ 라 간격은 0.027 m/s, 0.067 rad/s 로 이미 촘촘하다.

### 10.3 예측 — 원호 궤적

일정한 $(v, \omega)$ 로 움직이면 원호다. $T = 1.2\ \text{s}$ 동안 8점 ($t_j = 0.15j$), 로봇 좌표계:

$$
x(t) = \frac{v}{\omega}\sin(\omega t),\qquad y(t) = \frac{v}{\omega}\big(1 - \cos\omega t\big)\qquad(\omega \to 0:\ x = vt,\ y = 0)
$$

### 10.4 거르기와 점수

궤적 점과 장애물 점(LiDAR 360점 + 사람 예측점) 사이 최소 거리 $c$:

$$
\text{안전} \iff c > r_{\text{robot}} + 0.15 = 0.28\ \text{m}
$$

안전한 후보 안에서 각 항을 $[0, 1]$ 로 정규화($\mathcal N$)해 더한다:

$$
J(v, \omega) = 1.0\cdot\mathcal N\big(-\lVert \mathbf p_8 - \mathbf g \rVert\big) + 0.8\cdot\mathcal N\big(\min(c,\ 0.8)\big) - 2.0\,[v < 0] - 1.9\,[|v| \le 0.01]
$$

(궤적 끝이 조준점에 가까울수록 + 장애물에서 멀수록, 후진·정지는 감점.) $\arg\max J$ 를 고른다.
안전한 후보가 하나도 없으면 멈추고 조준점 쪽으로 제자리 회전.

### 10.5 바퀴 속도 — 차동 구동 역기구학 (강의 p125)

$$
\omega_L = \frac{v - \omega B/2}{r_w},\qquad \omega_R = \frac{v + \omega B/2}{r_w}\qquad(B = 0.16,\ r_w = 0.033)
$$

한 바퀴라도 모터 한계 $\omega_{\max} = 6.67\ \text{rad/s}$ (시작할 때 Webots 에서 읽어 대조)를 넘으면 **두 바퀴를 같은 비율로** 줄인다:

$$
s = \min\!\Big(1,\ \frac{0.999\,\omega_{\max}}{\max(|\omega_L|, |\omega_R|)}\Big),\qquad (\omega_L, \omega_R) \leftarrow s\,(\omega_L, \omega_R)
$$

회전 반경 $v/\omega$ 는 그대로, 느려지기만 한다. 한쪽만 자르면 궤적이 바뀐다 (전진하며 최대로 돌 때 바깥 바퀴가 한계를 12~44% 넘는다).

### 10.6 예상 질문

- **Q. 왜 pure pursuit 만 쓰지 않고 DWA?** A. pure pursuit 는 경로만 따라가고 장애물을 모른다. DWA 는 매 틱 LiDAR 를 직접 보고 부딪히는 명령을 **애초에 내지 않는다**. 조준점(look-ahead)은 DWA 의 목표로 함께 쓴다.
- **Q. 후보 119개는 적지 않나?** A. 개수보다 창의 폭이 작다 (가속 한계). 창 안은 이미 촘촘하다.
- **Q. 왜 가끔 떨리나(좌우 번갈아)?** A. 좁은 문 앞에서 왼쪽·오른쪽으로 비키는 후보의 점수가 비슷해 매 틱 번갈아 고른다 (88~92초, 2초에 12~14번). 개선 과제다.

## 14. 예상 질문 모음

### 전체

1. **Q. 전체 구조를 한 문장으로?** 센서로 위치를 추정하고 지도를 그리며(SLAM 의 단순판), 상태 기계가 목표를 정하면 A\* 가 경로를, DWA 가 바퀴 명령을 만든다.
2. **Q. ROS2·Nav2 를 안 쓴 이유?** 제출물이 파이썬 파일 하나 + README 이고, 채점 환경에 ROS2 가 있다고 가정할 수 없다. 대신 Nav2 의 구성(costmap 팽창, 전역 A\*, 지역 DWA, recovery)을 같은 이름으로 직접 구현했다.
3. **Q. 한 틱은 얼마나 걸리나?** 64 ms 틱 안에 끝난다. 시뮬레이션은 컨트롤러가 느려도 행동이 바뀌지 않는다 (`robot.step` 이 정확히 64 ms 씩 진행).

### 위치·지도

4. **Q. 위치 오차가 얼마나 되나?** 보통 20 cm 안팎. 카펫에서 튀면 1~3 m 까지 (정밀 스캔 매칭 재생 시 21~86 cm).
5. **Q. 나침반을 쓰는 건 절대 위치 아닌가?** 아니다. 나침반은 **방향** 센서(자력계)다. 위치는 주지 않는다. 대회 공지에서도 IMU 는 써도 된다고 했다.
6. **Q. log-odds 가 뭔가, 왜 쓰나?** $l = \log\frac{p}{1-p}$. 베이즈 갱신이 곱셈에서 **덧셈** 으로 바뀌어 빠르고, 0·1 근처에서 수치가 안정적이다.
7. **Q. 지도 크기는 어떻게 정했나?** apartment 벽 27개가 $x \in [-12.4, 0]$, $y \in [-13.1, 0]$ 에 있어 여유를 두고 16×16 m.

### 인지

8. **Q. 사과가 여러 개 겹쳐 보이면?** 연결 요소가 하나로 붙으면 모양 검사(가로로 김)에 걸릴 수 있다. 가까이 가서 다시 보면 떨어진다.
9. **Q. YOLO 를 항상 돌리지 않는 이유?** CPU 로 한 장 약 90 ms. 빨간 게 없는 장에서는 판단할 대상이 없다. 빨간 덩어리가 모양 검사를 통과했을 때만 돌린다.
10. **Q. 사람을 YOLO 로 안 찾나?** 카메라 시야 60°, LiDAR 는 360°. 로봇 뒤·옆에서 오는 사람은 LiDAR 로만 보인다. LiDAR 의 "지도에 없고 움직이는 것" 이 모양·옷과 무관하게 잡는다.

### 계획·제어

11. **Q. 경로가 구불구불한 이유?** 칸 경로를 다듬어도, DWA 가 장애물 여유와 조준점 사이에서 절충하고 0.3초마다 다시 계획한다. 좁은 곳에서 특히 흔들린다.
12. **Q. 이미 간 곳을 또 가는 이유?** 8.3 참고 — 실패한 목표가 바로 다시 뽑히고, 가짜 벽이 길을 막는다. 개선 과제.
13. **Q. 사과에 얼마나 가까이 가나?** 확정 위치에서 0.57 m 안이면 방문으로 친다. 실제 측정 최근접 0.47 m, 0.68 m.

### 안전·규칙

14. **Q. 보행자와 부딪히면?** Webots 보행자는 기구학적이라 로봇을 밀고 지나간다. 그래서 예측해 비킨다 (6.2). 측정 접촉 0초.
15. **Q. 벽에 끼거나 카펫에 걸리면?** 11장의 눌림 탈출. 그래도 헛돌면 위치가 틀어진다 (3.5). 바퀴 회전과 나침반 회전을 비교하는 미끄러짐 감지를 만들었고(기본 꺼짐), 실제 주행 효과를 재는 중이다.

## 15. 용어집

| 용어 | 뜻 |
|---|---|
| 오도메트리 (odometry) | 바퀴 회전으로 이동량을 적분하는 위치 추정 |
| 추측 항법 (dead reckoning) | 알려진 이동을 계속 더해 위치를 추정하는 방법 |
| log-odds | $\log\frac{p}{1-p}$. 확률의 곱을 덧셈으로 바꾼다 |
| 점유 격자 (occupancy grid) | 칸마다 "벽일 확률"을 담은 지도 |
| 역센서 모델 | "이런 측정이면 이 칸이 벽일 확률은?" — 우리는 맞음 +0.9, 빔 −0.4 |
| 브레젠험 (Bresenham) | 두 칸 사이 직선 위의 칸을 정수 연산으로 나열 |
| 팽창 (inflation) | 로봇을 점으로 보기 위해 벽을 로봇 반경만큼 부풀리는 것 (C-space) |
| 프론티어 (frontier) | 아는 빈 칸과 모르는 칸의 경계 — 탐색할 곳 |
| A\* | $f = g + h$ 가 작은 칸부터 펼치는 최단 경로 탐색 |
| 옥타일 거리 | 8방향 격자에서의 최단 거리 추정 (대각선 $\sqrt2$) |
| DWA | 낼 수 있는 속도 후보를 짧게 굴려 보고 최선을 고르는 지역 계획기 |
| 동적 창 (dynamic window) | 가속 한계 안에서 다음 순간 낼 수 있는 속도 범위 |
| 역기구학 | 원하는 $(v, \omega)$ → 좌·우 바퀴 각속도 |
| 스캔 매칭 | LiDAR 스캔을 지도에 맞춰 위치를 고치는 것 |
| 거리 변환 (distance transform) | 각 칸에서 가장 가까운 벽까지의 거리 |
| 가우스-뉴턴 | 제곱합 최소화를 선형화해 반복으로 푸는 방법 |
| 칼만 필터 | 예측(모델)과 측정을 불확실성으로 가중해 섞는 최적 추정기 |
| 게이트 (gating) | 예측에서 너무 먼 측정은 같은 대상으로 보지 않는 것 |
| HSV | 색상(H)·채도(S)·명도(V) 색공간. 조명에 덜 민감하다 |
| 연결 요소 (connected components) | 붙어 있는 픽셀 덩어리 |
| 핀홀 카메라 | 한 점을 통과한 빛이 영상면에 맺히는 가장 단순한 카메라 모델 |
| FSM | 유한 상태 기계 — 상태와 전이 조건으로 행동을 정리 |
| Supervisor | Webots 에서 월드 전체(정답 위치 포함)를 읽는 권한. 대회 주행에는 금지 |
