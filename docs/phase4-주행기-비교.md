# Phase 4 보강 — 국소 진동 추적과 DWA 도입

## 증상
사용자 보고: "코너 돌 때 걸린다", "오른쪽 구간에서 계속 진동한다."
`debug/out/mission.png` 에서 `(1.75, -1.5)` 한 점에 궤적이 매듭처럼 뭉쳐 있었다.

## 어떻게 찾았나
`debug/mission_check.py` 가 매 틱을 `debug/out/trace.csv` 로 남기게 하고,
"1초 동안 5 cm 도 못 간 구간" 을 뽑아 그때의 상태·목표·최근접거리를 봤다.

```
2초 이상 제자리에 머문 구간 8 개 중 5 개가 (+1.75, -1.5) — W4 벽 끝
제자리에 머문 시간 합계 39s / 전체 171s = 23%
```

## 틀렸던 가설 (기록용)
처음엔 "계획 경로가 벽에 붙어 있다(0.20 m)" 고 판단해 비용층을 넣었다.
그런데 그 지표에 결함이 있었다 — **경로의 첫 점은 로봇 자신의 위치**라,
로봇이 벽에 붙어 있으면 경로가 나쁜 것처럼 보였다.
출발점을 빼고 다시 재니 경로 여유는 멀쩡했다 (중앙값 0.40 m, 최소 0.29 m).

비용층은 측정 결과 이 맵에서 도움이 안 됐다 (171s → 220s → 376s).
기능은 남겨 두되 기본값을 껐다. `PLANNER_SOFT_WEIGHT`, `PLANNER_CARVED_COST`.

## 실제로 고친 것 1 — 좁은 여유가 쓸모없었다
```
좁은 여유(squeeze) = 0.13 + 0.10 = 0.23 m
정지거리                          = 0.23 m   ← 똑같다
```
squeeze 로 만든 경로는 만들자마자 정지가 걸린다. 게다가 프론티어 도달 판정도
이 값을 쓰므로 갈 수 없는 목표를 계속 골랐다 (경로 계획 실패가 전체 틱의 13.4%).
→ 좁은 여유도 정지거리보다 `PLANNER_SQUEEZE_SLACK` 만큼은 크도록 유도식으로 바꿨다.

## 실제로 고친 것 2 — DWA 도입 (핵심)
증거가 한 곳을 가리켰다: **근접 사고 전부가 "탈출" 중에 났고, 제자리 시간의
대부분도 정지·대기·탈출 고리였다.** 즉 문제는 파라미터가 아니라 주행 방식이었다.

- 기존: 경로를 따라가되 위험하면 멈춘다 → 정지·대기·후진·탈출 상태가 필요
- DWA: (전진, 회전) 후보를 뿌려 1.2초 앞을 모의주행하고 점수로 고른다
  → 애초에 부딪히는 명령을 내지 않으므로 그런 상태가 필요 없다
  → 가속 한계를 두므로 명령이 튀지 않는다 (부드러움)

`follower.step()` 이 `config.FOLLOW_USE_DWA` 로 둘 중 하나를 고른다.
입출력이 같아서 `mission.py` 는 어느 쪽인지 모른다.
